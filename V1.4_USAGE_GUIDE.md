## Prerequisites

### Hardware Required
- Arduino UNO (fully wired per V1.4_WIRING_GUIDE.md)
- ESP8266 NodeMCU (fully wired per V1.4_WIRING_GUIDE.md)
- Level shifter or voltage divider for UART communication
- USB cables for both boards
- Power supply (5V for UNO, 3.3V for ESP8266 recommended)

### Software Required
- Arduino IDE 1.8.x or 2.x
- ESP8266 board support (install via Board Manager)
- Required libraries:
  - **For UNO**: Servo, Adafruit_NeoPixel, NewPing
  - **For ESP8266**: ESP8266WiFi, PubSubClient, ArduinoJson, TinyGPSPlus, LittleFS

### MQTT Broker
- Local MQTT broker (e.g., Mosquitto) or cloud service (e.g., HiveMQ, CloudMQTT)
- Note the broker IP address and port (default: 1883)

## First-Time Setup

### 1. Install Arduino Libraries

**For Arduino UNO:**
```
Tools → Manage Libraries → Search and install:
- Servo (by Arduino)
- Adafruit NeoPixel (by Adafruit)
- NewPing (by Tim Eckel)
```

**For ESP8266:**
```
Tools → Manage Libraries → Search and install:
- PubSubClient (by Nick O'Leary)
- ArduinoJson (by Benoit Blanchon) - version 6.x
- TinyGPSPlus (by Mikal Hart)
- ESP8266WiFi (included with ESP8266 board support)
- LittleFS (included with ESP8266 board support)
```

### 2. Install ESP8266 Board Support

1. Open Arduino IDE
2. Go to `File → Preferences`
3. Add to "Additional Board Manager URLs":
   ```
   http://arduino.esp8266.com/stable/package_esp8266com_index.json
   ```
4. Go to `Tools → Board → Boards Manager`
5. Search "esp8266" and install "ESP8266 by ESP8266 Community"

## Uploading Firmware

### ⚠️ CRITICAL: UNO Upload Procedure

**Arduino UNO uses Hardware Serial (D0/D1) for ESP8266 communication.**
**You MUST disconnect these pins during upload:**

1. **DISCONNECT** the TX/RX wires between UNO and ESP8266:
   - UNO D0 (RX) ← disconnect from level shifter
   - UNO D1 (TX) ← disconnect from level shifter

2. Upload the firmware:
   ```
   Tools → Board → Arduino UNO
   Tools → Port → (select your COM port)
   Sketch → Upload
   ```

3. **Wait for "Done uploading"** message

4. **RECONNECT** the TX/RX wires

### ESP8266 Upload Procedure

**ESP8266 also uses Hardware Serial (GPIO1/GPIO3) for UNO communication.**
**Same disconnect procedure required:**

1. **DISCONNECT** the TX/RX wires between ESP8266 and UNO:
   - ESP8266 GPIO1 (TX) ← disconnect from level shifter
   - ESP8266 GPIO3 (RX) ← disconnect from level shifter

2. Upload the firmware:
   ```
   Tools → Board → NodeMCU 1.0 (ESP-12E Module)
   Tools → Upload Speed → 115200
   Tools → CPU Frequency → 80 MHz
   Tools → Flash Size → 4MB (FS:2MB OTA:~1019KB)
   Tools → Port → (select your COM port)
   Sketch → Upload
   ```

3. **Wait for "Done uploading"** message

4. **RECONNECT** the TX/RX wires

## Testing Communication

### 1. Test UNO → ESP8266 Communication

**Monitor ESP8266 Serial Output:**

1. Upload ESP8266 firmware with TX/RX disconnected
2. Disconnect USB from ESP8266
3. Reconnect TX/RX wires (through level shifter)
4. Reconnect ESP8266 USB
5. Open Serial Monitor:
   ```
   Tools → Serial Monitor
   Baud: 9600
   ```

**Expected output:**
```
Wi-Fi connected: 192.168.1.XXX
MQTT connected
[UNO] temp_c:25.3
[UNO] humidity:%:65.2
[UNO] soil:%:45.0
...
```

If you see `[UNO]` prefixed messages, UNO→ESP8266 communication is working!

### 2. Test MQTT Publishing

**Use MQTT client (e.g., MQTT Explorer, mosquitto_sub):**

```bash
# Subscribe to all greenhouse topics
mosquitto_sub -h 192.168.1.100 -t "greenhouse/#" -v
```

**Expected output:**
```
greenhouse/sensor/temperature {"value":25.3,"unit":"C","timestamp":12345}
greenhouse/sensor/humidity {"value":65.2,"unit":"%","timestamp":12346}
greenhouse/sensor/soil {"value":45.0,"unit":"%","timestamp":12347}
greenhouse/sensor/light {"value":512,"unit":"raw","timestamp":12348}
greenhouse/sensor/flame {"value":1023,"unit":"raw","timestamp":12349}
greenhouse/sensor/ultrasonic {"value":35.2,"unit":"cm","timestamp":12350}
```

### 3. Test Device Control

**Publish MQTT command to turn on pump:**

```bash
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/pump" -m "1"
```

**Expected:** Pump relay should click ON

```bash
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/pump" -m "0"
```

**Expected:** Pump relay should click OFF

## Sensor Data Format

All sensor data is published in **standardized JSON format**:

```json
{
  "value": 25.3,
  "unit": "C",
  "timestamp": 12345
}
```

### Sensor Topics and Units

| Topic | Unit | Description |
|-------|------|-------------|
| `greenhouse/sensor/temperature` | `"C"` | Temperature in Celsius |
| `greenhouse/sensor/humidity` | `"%"` | Relative humidity (0-100%) |
| `greenhouse/sensor/soil` | `"%"` | Soil moisture (0-100%) |
| `greenhouse/sensor/light` | `"raw"` | Light sensor ADC (0-1023) |
| `greenhouse/sensor/flame` | `"raw"` | Flame sensor ADC (0-1023) |
| `greenhouse/sensor/ultrasonic` | `"cm"` | Distance in centimeters |
| `greenhouse/sensor/gps` | `"lat,lon"` | GPS coordinates |

### Example: Parse JSON in Python

```python
import json
import paho.mqtt.client as mqtt

def on_message(client, userdata, msg):
    data = json.loads(msg.payload)
    print(f"{msg.topic}: {data['value']} {data['unit']}")

client = mqtt.Client()
client.on_message = on_message
client.connect("192.168.1.100", 1883)
client.subscribe("greenhouse/sensor/#")
client.loop_forever()
```

## Device Control

### Relay Control

**Topic format:** `greenhouse/relay/<device>`
**Payload:** `1` (ON) or `0` (OFF)

**Examples:**

```bash
# Turn ON pump
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/pump" -m "1"

# Turn OFF pump
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/pump" -m "0"

# Turn ON fan
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/fan" -m "1"

# Turn ON auxiliary fan
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/auxfan" -m "1"

# Turn ON lamp
mosquitto_pub -h 192.168.1.100 -t "greenhouse/relay/lamp" -m "1"
```

### Servo Control

**Topic:** `greenhouse/servo/position`
**Payload:** Angle in degrees (0-180)

```bash
# Open window to 90 degrees
mosquitto_pub -h 192.168.1.100 -t "greenhouse/servo/position" -m "90"

# Close window (0 degrees)
mosquitto_pub -h 192.168.1.100 -t "greenhouse/servo/position" -m "0"
```

### LED Control

**Topic:** `greenhouse/led/mode`
**Payload:** `OFF`, `TEMP`, `HUMIDITY`, `SOIL`, `LIGHT`, `FLAME`, `ALERT`

```bash
# Temperature color mode (blue→green→red)
mosquitto_pub -h 192.168.1.100 -t "greenhouse/led/mode" -m "TEMP"

# Turn off LED
mosquitto_pub -h 192.168.1.100 -t "greenhouse/led/mode" -m "OFF"

# Alert mode (red blink)
mosquitto_pub -h 192.168.1.100 -t "greenhouse/led/mode" -m "ALERT"
```

## Auto Control Mode

**v1.4 introduces automatic device control based on sensor thresholds.**

### Enable Auto Control

```bash
# Enable auto control
mosquitto_pub -h 192.168.1.100 -t "greenhouse/auto/enable" -m "1"

# Disable auto control (manual mode)
mosquitto_pub -h 192.168.1.100 -t "greenhouse/auto/enable" -m "0"
```

### Default Thresholds

```cpp
temp_max = 35.0°C        // Turn ON fan when temp > 37°C (35 + 2 hysteresis)
temp_hysteresis = 2.0°C  // Turn OFF fan when temp < 33°C (35 - 2)

soil_min = 30.0%         // Turn ON pump when soil < 25% (30 - 5 hysteresis)
soil_hysteresis = 5.0%   // Turn OFF pump when soil > 35% (30 + 5)

light_threshold = 300    // Turn ON lamp when light < 300
flame_threshold = 500    // Send alert when flame < 500 (fire detected)
```

### Auto Control Logic

**When auto control is ENABLED:**

1. **Temperature → Fan:**
   - IF temp > 37°C → Turn ON fan
   - IF temp < 33°C → Turn OFF fan
   - (Prevents oscillation with ±2°C hysteresis)

2. **Soil Moisture → Pump:**
   - IF soil < 25% → Turn ON pump
   - IF soil > 35% → Turn OFF pump
   - (Prevents oscillation with ±5% hysteresis)

3. **Light Level → Lamp:**
   - IF light < 300 → Turn ON lamp
   - IF light > 300 → Turn OFF lamp

4. **Flame Detection → Alert:**
   - IF flame < 500 → Send MQTT alert (once, debounced)
   - IF flame > 500 → Clear alert

### Customize Thresholds

**Topic:** `greenhouse/auto/thresholds`
**Payload:** JSON object

```bash
# Set custom thresholds
mosquitto_pub -h 192.168.1.100 -t "greenhouse/auto/thresholds" -m '{
  "temp_max": 30.0,
  "temp_hysteresis": 1.5,
  "soil_min": 40.0,
  "soil_hysteresis": 3.0,
  "light_threshold": 400,
  "flame_threshold": 600
}'
```

## LED Status Indicators

The NeoPixel LED provides visual feedback:

### Color Modes

**Temperature Mode (default):**
- **Blue** (0-25°C): Cool
- **Green** (25-35°C): Optimal
- **Red** (35°C+): Hot

**Humidity Mode:**
- **Red** (0-30%): Dry
- **Yellow** (30-70%): Optimal
- **Blue** (70-100%): Humid

**Soil Moisture Mode:**
- **Red** (0-30%): Dry soil
- **Yellow** (30-70%): Moist
- **Blue** (70-100%): Wet

**Light Mode:**
- **Brightness** proportional to light level

**Flame Alert Mode:**
- **Red blinking** (500ms interval): Fire detected!

**Off Mode:**
- LED turned off

## Troubleshooting

### Problem: UNO won't upload

**Cause:** D0/D1 pins connected to ESP8266 during upload
**Solution:**
1. Disconnect D0 and D1 wires from level shifter
2. Upload firmware
3. Reconnect D0 and D1

### Problem: ESP8266 won't upload

**Cause:** GPIO1/GPIO3 pins connected to UNO during upload
**Solution:**
1. Disconnect GPIO1 (TX) and GPIO3 (RX) wires from level shifter
2. Upload firmware
3. Reconnect GPIO1 and GPIO3

### Problem: ESP8266 keeps rebooting

**Symptoms:** Serial Monitor shows:
```
 ets Jan  8 2013,rst cause:4, boot mode:(3,6)
wdt reset
```

**Cause:** Watchdog timer reset (code blocked too long)
**Solution:** Already fixed in v1.4 with `yield()` calls. If still occurs:
- Check GPS module isn't blocking
- Check ultrasonic sensor wiring

### Problem: No MQTT connection

**Check:**
1. Wi-Fi credentials correct? (check Serial Monitor for IP address)
2. MQTT broker running? (`mosquitto -v` to test)
3. Broker IP correct in code?
4. Firewall blocking port 1883?

**Test broker connectivity:**
```bash
# From another computer
mosquitto_pub -h 192.168.1.100 -t "test" -m "hello"
mosquitto_sub -h 192.168.1.100 -t "test"
```

### Problem: No sensor data on MQTT

**Check Serial Monitor on ESP8266:**
- Do you see `[UNO] temp_c:XX.X` messages?
  - **YES:** UART communication OK, check MQTT topic subscription
  - **NO:** Check wiring between UNO and ESP8266

**Check level shifter:**
- UNO D1 (5V TX) → Level shifter → ESP8266 GPIO3 (3.3V RX)
- UNO D0 (5V RX) → Level shifter → ESP8266 GPIO1 (3.3V TX)
- Common ground connected?

### Problem: Relays toggle rapidly (oscillation)

**Cause:** No hysteresis in auto control
**Solution:** Already fixed in v1.4 with hysteresis. If still occurs:
- Increase hysteresis values:
  ```cpp
  temp_hysteresis = 3.0;  // Increase from 2.0
  soil_hysteresis = 10.0; // Increase from 5.0
  ```

### Problem: MQTT spam with flame alerts

**Cause:** No debounce on flame sensor
**Solution:** Already fixed in v1.4 with debounce flag. Alert sent only once when flame detected.

### Problem: GPS data is `0.000000,0.000000`

**Causes:**
1. GPS module not connected
2. GPS has no fix (indoor, no satellite visibility)
3. GPS baud rate mismatch

**Solution:**
1. Move GPS module outdoors or near window
2. Wait 1-2 minutes for satellite lock
3. Check GPS module baud rate (default 9600 in code)

### Problem: Ultrasonic reads 0 cm

**Causes:**
1. Wrong wiring (TRIG/ECHO pins swapped)
2. Module not powered (VCC/GND)
3. Object too close (<2cm) or too far (>400cm)

**Solution:**
1. Check wiring: TRIG=D6, ECHO=D7, VCC=5V, GND=GND
2. Test with object at 10-50cm distance

### Problem: DHT11 reads 0°C or NaN

**Causes:**
1. Wrong wiring
2. No pull-up resistor (4.7kΩ required)
3. Faulty sensor

**Solution:**
1. Check wiring: DATA=A3, VCC=5V, GND=GND
2. Add 4.7kΩ resistor between DATA and VCC
3. Wait 2 seconds after power-on before reading

## Default Pin Summary

### Arduino UNO Pins
```
D0  (RX) → ESP8266 via level shifter
D1  (TX) → ESP8266 via level shifter
D2       → Relay 1 (Pump)
D3       → Relay 2 (Fan)
D4       → Relay 3 (AuxFan)
D5       → Relay 4 (Lamp)
D6       → Ultrasonic TRIG
D7       → Ultrasonic ECHO
D9       → Servo control
D10      → NeoPixel data
A0       → Soil moisture sensor
A1       → LDR (light sensor)
A2       → Flame sensor
A3       → DHT11 data
```

### ESP8266 Pins
```
GPIO1 (TX)  → UNO via level shifter
GPIO3 (RX)  → UNO via level shifter
GPIO4 (D2)  → GPS TX (SoftwareSerial RX)
GPIO5 (D1)  → GPS RX (SoftwareSerial TX)
```
